Cited criterion text (from requirements.md):
- 2.1: WHEN a shopper applies an `active` Gift_Card code to a Cart whose subtotal is at most the Gift_Card balance, THE Shop_API SHALL subtract the Cart subtotal from the Gift_Card balance.
- 2.3: IF a Gift_Card balance exceeds 1000 dollars, THEN THE Shop_API SHALL reject redemption with HTTP 422 and error `balance_too_high`.
- 2.5: IF the Cart subtotal exceeds the Gift_Card balance, THEN THE Shop_API SHALL return HTTP 409 with error `insufficient_balance` and leave the balance unchanged.
- 2.6: WHEN two redemptions of one Gift_Card run concurrently, THE Shop_API SHALL apply them one at a time so the balance never goes below 0.
- 4.1: THE Shop_API SHALL keep a Gift_Card `active`, with no expiry date, until a staff member voids it under 3.1.
- 5.1: WHEN a Gift_Card balance or status changes, THE Shop_API SHALL append a ledger entry with the code, old value, new value, actor id, and UTC timestamp.
- 5.2: IF the ledger write fails, THEN THE Shop_API SHALL reject the change with HTTP 503 and error `ledger_unavailable`.
- 5.3: IF the ledger write fails after a Payment_Provider charge, THEN THE Shop_API SHALL refund the charge.
- 5.4: IF the refund in 5.3 fails, THEN THE Shop_API SHALL return HTTP 503 with error `refund_failed` instead of `ledger_unavailable`.
